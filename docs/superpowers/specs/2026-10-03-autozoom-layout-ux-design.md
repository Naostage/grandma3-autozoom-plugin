# AutoZoom 2.0 — Layout UI and "follow the console" design

Date: 2026-10-03 · Branch: `feat/ux-ui` (stacked on `fix/audit-2.5`) · Target: grandMA3 2.5.x
Prototype: `docs/prototype/autozoom-layout-prototype.html` (also published as a private artifact)

## 1. Goal

Make AutoZoom usable by a programmer (setup) and an operator (live) without the command line or the System Monitor.

Pain points this design must fix:

1. Setup is tedious (one `Lua "AZ:EnableFixture(...)"` per fixture, sequences created by hand).
2. No visibility: no display of which fixture follows which marker, at what size, or why it isn't working.
3. State is lost when the plugin reloads or the show is reopened.
4. Live control is clumsy.
5. AutoZoom state cannot be recalled from cues: changing which fixture follows a marker in a sequence does not carry AutoZoom with it.

Backward compatibility with 1.x shows, commands and object names is **not** required.

## 2. Core decisions

| Topic | Decision |
|---|---|
| Source of truth | The desk. The marker a fixture follows and its XYZ offset are read live from the fixture's `XYZ_MArker` and `XYZ_X/Y/Z` output values, so cues recall them natively. |
| What cues recall for AutoZoom | Only which fixtures are **armed**, via one command in the cue: `Lua "AZ:Arm('101,102')"` (the full list; fixtures not listed are disarmed). |
| UI surface | A grandMA3 **Layout** generated by the plugin in its own **"AutoZoom" DataPool** (BeatGrid model). Popups only for rare actions (Setup, prompts). |
| Helpers | **Capture** (write current arms into a cue) and **tap-to-program** (put marker + XYZ offset + zoom/iris minimum in the programmer). |
| Beam size | Not cue data. Global size fader + optional fixed size per fixture, saved with the show. |
| Persistence | One JSON string in `GlobalVars` (survives show save/load, verified). |

## 3. Verified platform facts (grandMA3 onPC 2.5.0.3, probe of 2026-10-03)

- `GetRTChannel(uiChannel).info.value_after_master` returns the live **output** value including playback, with `info.cue_part` naming the source (`Programmer` or `DataPool p.7.seq.cue.part`). For `XYZ_MArker` the value is the marker **CID**.
- UI channel lookup: `GetSubfixture(i).fid` → index `i`; `GetUIChannelIndex(i, attrIndex)`; `GetAttributeByUIChannel(uich).name`. Attribute names: `XYZ_X`, `XYZ_Y`, `XYZ_Z`, `XYZ_Flip`, `XYZ_MArker`, `Zoom`, `Iris`.
- `HookObjectChange` on a fixture returned no handle and no events: **poll** (cost is negligible).
- DataPool child 7 is Sequences in 2.5 (access children by name, never by index).
- Layout from Lua works (`Store Layout`, `Assign Macro … At Layout`); element properties include `CUSTOMTEXTTEXT`, `CUSTOMTEXTCOLOR` / `BORDERCOLOR` (hex RGBA strings), `POSX/POSY/WIDTH/HEIGHT`, `ACTION`, `APPEARANCE`, `NOTE`. 300 text updates at 30 Hz averaged 0.04 ms each and left nothing in the Oops list.
- `SetVar(GlobalVars(), key, value)` survives show save/reload (20 kB string OK).
- `Timer` keeps firing while `TextInput` or `MessageBox` is open.
- Markers are identified by **CID** (their FID can be unset). Fixtures inside groups (e.g. `Stage 1/Fixtures/SPOTS/…`) have `POSX/Y/Z` relative to their parent.

## 4. Architecture

TypeScript → Lua (TypeScriptToLua), one plugin, modules with one job each:

| Module | Responsibility | Depends on |
|---|---|---|
| `runtime` | Single live instance, start/stop, update loop, error containment, commands | `Desk` interface, `engine`, `ui` view model, `store` |
| `desk` | The `Desk` interface: every console operation the runtime needs. Lets the runtime be tested with a fake desk | — |
| `console` | `MaDesk`, the grandMA3 implementation of `Desk`: patch scan, UI channel lookup, live attribute reads, PSN reads, sequence/fader/cue access, layout, prompts, command execution | MA3 API only |
| `engine` | Pure logic: aim point, zoom/iris math, per-fixture state machine | nothing (pure) |
| `ui` view model | Pure: layout geometry and the text/colours of every cell | `engine` |
| `store` | Config JSON encode/decode/validation (I/O goes through `Desk`) | — |

Capture, tap-to-program, Setup and Size are runtime commands built on `Desk` and pure helpers.

`engine` stays pure so the Lua test harness can cover it exhaustively.

### 4.1 Runtime instance

- One instance lives in a global (`AZ`). Its identity is stamped into `AddonVars("AutoZoom")`; after a show load or plugin re-run a stale instance is detected, stopped and replaced, so update loops never stack (Pro Plugins `ShowSingletonUtils` pattern).
- Running the plugin = install/repair + start. Every object is found by name or created, so running it again is always safe.
- Auto-start on show load is **out of scope**; the offline layout shows a **Start** button, and a "Start AutoZoom" macro is created.

### 4.2 Update loop

- `Timer(tick, 1/rate, 0, cleanup)`; default rate 30 Hz (setting).
- Each tick: read PSN marker positions → for each managed fixture read live `XYZ_MArker` and `XYZ_X/Y/Z` → run `engine` → write changed fader values → refresh changed layout cells.
- An error while handling one fixture is logged once (per fixture and message) and that fixture is skipped; the loop never dies from a single fixture.
- `cleanup` (on stop, error or show change) releases every AutoZoom fader and switches the layout to its offline state.

### 4.3 DataPool "AutoZoom" contents

| Object | Name | Purpose |
|---|---|---|
| Layout | `AutoZoom` | The UI |
| Sequence per fixture | `AZ_ZOOM_<fid>` | One cue: Zoom at maximum (`At Absolute Physical <zoom max>`); driven by its Temp fader |
| Sequence per fixture (if iris) | `AZ_IRIS_<fid>` | One cue: Iris at maximum; driven by its Temp fader |
| Sequence | `AZ_SIZE` | Global size fader (Master fader read by the plugin) |
| Sequences | `AZ <cell key>` (one per layout cell, see §15.1) | Layout cells: cue 1 runs `Lua "if AZ then AZ:<Command>(...) end"` (no error when AutoZoom is not running); display-only cells have no command. Live text and colours are written to the layout element (`CUSTOMTEXTTEXT`, `CUSTOMTEXTCOLOR`, `BORDERCOLOR`), the route verified in probe 1 |
| Macro | `AZ Start` | One line `Call Plugin "GMA3 Autozoom"`: starts AutoZoom after a show load or reboot; created once, the operator assigns it where they want. Renaming the plugin breaks it |

Old objects in other datapools (1.x `AZ_ZOOM_*` etc.) are not migrated.

## 5. Control logic (engine)

Per managed fixture, every tick:

```
inputs: armed (config), cid = live XYZ_MArker, off = live XYZ_X/Y/Z,
        marker position from PSN (by cid), fixture stage position, size
state:
  not running            → Offline        : faders released
  not armed              → Disarmed       : faders released, never touched
  cid == 0               → Armed·no marker: faders released (cue's own zoom/iris apply)
  cid not a patched marker → Error        : faders released
  no PSN data for cid    → No PSN         : hold last fader values
  otherwise              → Tracking / Too wide / Too small
```

- **Aim point** = marker position + offset (rotation per P2). **Fixture position** = its patch position composed with every parent group's position (and rotation per P9).
- **Zoom/iris**: unchanged 1.x math (full cone angle `2·atan(size/2 / d)`, linear map onto the fixture type's zoom range; below minimum zoom, iris ratio `size / beam-at-min-zoom` mapped onto the iris physical range, which is 0..1 in GDTF and verified on the Robin Esprite). Results clamped to 0..100.
  - `Too wide`: wanted angle > zoom max → zoom 100, iris 100.
  - `Too small`: iris ratio < iris min → iris 0.
- **Fader resolution**: send values with 0.1 % resolution if P10 confirms fractional `SetFader`, else whole percent; only send when changed.
- **Release** = Temp fader to 0 (the sequence releases, so the fixture's own cue values apply).

Fixtures managed = every fixture of an XYZ-enabled fixture type with a Zoom channel, found by the patch scan (types matched by fixture type **and** mode). Markers = every MArker fixture, keyed by CID.

## 6. Layout

Generated by **Rebuild** (also run at install); elements are tagged through their `Note` so the plugin finds them again. Refresh writes a property only when its value changed.

**Header:** Status (Running/Offline, PSN markers live x/y) · Start/Stop · Capture · Setup · Arm all · Disarm all · `AZ_SIZE` fader with its value in metres.

**One row per managed fixture:**

| Cell | Content | Tap |
|---|---|---|
| Arm | FID + name; green armed / grey disarmed | Toggle arm |
| One cell per marker | Lit where the fixture follows that marker: green (tracking), amber (no PSN), dashed (disarmed); red **P** when that fixture/marker is in the programmer | Tap-to-program (§8) |
| State | Tracking / Armed·no marker / Disarmed / No PSN for marker N / Too wide / Too small / Error, plus "following <marker> (+offset)" | — |
| Distance | Distance to aim point, achieved beam size | — |
| Zoom, Iris | Percent + bar | — |
| Size | "Global" or fixed metres, and the target size | Prompt: metres or back to Global |

Marker column headers show name, CID and PSN status. Offline state: everything greyed, header shows **Start**.

## 7. Capture (write arms into a cue)

1. Tap **Capture** → button turns amber "Select a sequence…" with a 15 s countdown.
2. Select the target sequence: tap it in the Sequence pool or press an executor's Select key (the plugin watches `SelectedSequence()`; `Go` does not count, so nothing fires).
3. A prompt (TextInput) opens, pre-filled with the cue **selected in the Sequence Sheet** if any, else the sequence's **running cue**; empty if neither. Enter to confirm or type another cue number.
4. The plugin writes `Lua "if AZ then AZ:Arm('<sorted armed fids>') end"` into that cue's command: other commands are kept, any previous `AZ:Arm(...)` is replaced.
5. Feedback on the layout and in the System Monitor: "Stored in Seq 12 'Main' cue 3".

Cancel: tap Capture again, Esc in the prompt, or timeout. Unknown cue → nothing written, message shown.

## 8. Tap-to-program and Setup

Tapping a marker cell (fixture × marker) **merges** into the programmer (no ClearAll):

- `XYZ_MArker` = marker CID
- `XYZ_X/Y/Z` = offset from Setup
- Zoom and Iris at their physical minimum (the base AutoZoom crossfades from)

Tapping the same cell again releases those values from the programmer. The user then stores cues the normal way.

**Setup** (popup) — saved in config:

- XYZ offset source: **XYZ preset** (preset number; only `XYZ_X/Y/Z` are recalled from it) or **Values** (X, Y, Z in metres, typed in the dialog: grandMA3's `MessageBox` offers text inputs and selectors, not faders).
- Size fader range (default 0.5–5 m), refresh rate.
- Rebuild layout, rescan patch.

## 9. Size

- Global: `AZ_SIZE` Master fader 0–100 % mapped to the range from Setup.
- Per fixture: optional fixed size in metres (prompt from the Size cell); overrides Global.
- Missing `AZ_SIZE` → recreated on Rebuild; meanwhile the last value is used and a warning shown once.

## 10. Persistence

`GlobalVars` key `AutoZoom.config`, JSON:

```json
{ "v": 1, "armed": [101, 102], "size": { "104": 1.5 }, "range": [0.5, 5],
  "rate": 30, "offset": { "source": "preset", "preset": "2.12", "values": [0, 0, 0] } }
```

Written on every change (debounced 1 s). Invalid or missing JSON → defaults, with a warning. Fixtures in `armed`/`size` that no longer exist are dropped on load.

## 11. Commands

All through the global: `Lua "AZ:<Command>(...)"`.

| Command | Effect |
|---|---|
| `Start()`, `Stop()` | Start/stop the loop |
| `Arm('101,102')` | Set the armed list exactly (what Capture writes) |
| `ArmToggle(101)`, `ArmAll()`, `DisarmAll()` | Arm edits |
| `Capture()`, `Program(fid, cid)`, `Setup()` | UI actions (called by layout buttons) |
| `Size(fid, metres \| 'global')` | Per-fixture size |
| `Rebuild()`, `Rescan()`, `Status()` | Maintenance; `Status` prints a summary |

## 12. Error handling

- Every MA3 call that is not verified on 2.5 goes through a guarded wrapper; failures are logged once with context and degrade (e.g. Capture without `SelectedSequence` asks for the sequence number too).
- Layout element missing (user deleted it) → next Rebuild re-appends it (the layout itself is kept); refresh skips missing elements silently.
- PSN lost → hold last values and show it; marker CID unknown → release and show Error.

## 13. Testing

- **Lua harness** (`tests/harness.lua`, `npm test`): extend the grandMA3 mock with `GetSubfixture`, `GetUIChannelIndex`, `GetRTChannel`, `GetAttributeIndex`, `GlobalVars`/`SetVar`/`GetVar`, `SelectedSequence`, layout and cue objects. Cover: engine states and math (incl. offsets and parent positions), arm/recall parsing, Capture command rewriting, config round-trip, stale-instance replacement, error containment.
- **Probe 2** on 2.5.0.3 for P1–P10 before implementing the dependent parts.
- **Manual console checklist** in the implementation plan: install on a fresh show, Rebuild, arm, follow via cues, Capture into running and selected cue, tap-to-program with preset and values, save/reload show, stop/start, PSN loss.

## 14. Out of scope

Auto-start on show load (DMX remote trick), custom "AZ Control" fixture type, hooks, multi-instance sub-fixtures beyond position composition, migrating 1.x shows, a web/network UI.

## 15. Addendum (2026-10-05, after the first console run)

### 15.1 Layout appearances (tinted fills)

Layout elements showed the bound macro's default "paper" appearance. Every cell now gets a tinted fill from a small set of **AutoZoom appearances**, BeatGrid-style:

| Kind | Name | IMAGERGBA | Used for |
|---|---|---|---|
| tracking | `AZ Tracking` | `137A38E0` | status Running, armed, live marker header, followed marker (tracking/too-wide/too-small), state Tracking |
| warn | `AZ Warn` | `7A6A10D9` | state Too wide / Too small |
| nopsn | `AZ No PSN` | `85520AD9` | marker header without PSN, followed marker without PSN, state No PSN |
| error | `AZ Error` | `851F1AD9` | status Offline, state Unknown marker |
| programmer | `AZ Programmer` | `8F211CE6` | matrix cell in the programmer (P) |
| capture | `AZ Capture` | `B8650FE0` | Capture / Offset pick waiting |
| button | `AZ Button` | `24283AE0` | tappable header cells, Size cells |
| header | `AZ Header` | `171C3DB8` | AZ_SIZE value and message cells |
| idle | `AZ Idle` | `10121CD9` | everything else (disarmed, empty matrix cells, values) |

- Appearances live in the show's **Appearances pool** (`ShowData().Appearances`) — appearances cannot live in a data pool, so this is the one exception to "everything in DataPool AutoZoom". They are found by name (`AZ …`), created when missing, and their `IMAGERGBA` is (re)applied at every install/Rescan; never duplicated.
- The AZ appearances occupy a contiguous block of free numbers from 9001 (BeatGrid's `Resize` + `Create(no, GetChildClass())`), so they stay clear of the operator's own appearances; AZ appearances found below 9001 (2.0.0.1 build) are deleted and recreated there.
- Every cell is a sequence `AZ <key>` in the AutoZoom pool (cue 1 runs the cell's command; display-only cells have none, element Action `Pause`, clickable cells `Go+`); the plugin sets the sequence's `Appearance` when the cell's kind changes (same write-only-on-change rule as the text); element `Appearance` stays empty (BeatGrid model). Macro-bound elements showed the macro's paper look on the console and no fill.
- Rebuild (Rescan/install) edits the layout **in place**: the `AutoZoom` layout object is stored only when missing and never deleted (operator views reference it). Elements are matched by their `AZ:<key>` note and reused; elements whose key is gone are removed with `layout:Delete(no)` (highest `No` first); elements without an `AZ:` note are never touched.
- Elements hide the bound object's name, icon, ID, CID, value and bar and draw no border (booleans `false`, as BeatGrid does).
- Text stays white (`E6E8EBFF`), muted (`8E96A3FF`) for the message cell.

### 15.2 Offset preset pick

A header cell **Offset** shows the current offset source ("Preset 2.30" / "0/0/0.3 m"). Tapping it starts a pick, the same way FXMAker/BounceMAker/FlyoutMAker pick presets on 2.5 (verified from their 2.5 builds):

1. Only while AutoZoom runs (refused when stopped; Stop cancels a pick). The cell turns to the capture appearance: "Tap a preset… / N s · tap to cancel", 10 s timeout; tapping Offset again cancels.
2. The update loop polls `CmdObj().LastCommand`; when it differs from the value at pick start and, anchored at its start, reads `[OK:] [At|Go+|Call] [DataPool <n>] Preset <p>.<q>` (case-insensitive), that preset is picked. Other commands are ignored (the pick keeps waiting); one that names a preset otherwise (Store/Delete/Label/…) logs `Preset pick ignored "<cmd>"` once. AutoZoom's own Program commands re-take the baseline (LastCommand and undo state) so they are never picked.
3. The undo state (`UndoIndex`, entry count, top entry name) is recorded at pick start. The tap's effect is undone with `Oops /nc` (while `CurrentProfile().OopsProgrammer` is temporarily `true`) only if the undo state changed since then **and** the top undo entry (`CmdObj().Undos[UndoIndex + 1].Name`) is that preset command: compared after stripping ANSI colour codes and a leading `OK:`, collapsing whitespace and lowercasing, it equals the command or ends with it, and it does not start with store/delete/copy/move/label/edit/update/assign/attribute. Otherwise nothing is undone.
4. The config's offset becomes `{ source: "preset", preset: "<p>.<q>" }` (or `"DataPool <n> Preset <p>.<q>"` when the command named a data pool); saved with the show. A System Monitor line records the LastCommand and undo name seen (diagnostics for the console checklist).
5. Tap-to-program uses `Attribute "XYZ_X" Thru "XYZ_Z" At Preset <p>.<q>`, or `… At DataPool <n> Preset <p>.<q>` for a data-pool address.

### 15.3 Simplification (2026-10-05, after the second console run)

AutoZoom already follows the marker that the cues set, so the arm state no longer needs to be recalled from cues.

- **Capture is removed**: the layout cell, the runtime flow (sequence selection, cue prompt, cue command rewrite) and the Desk methods it used (`selectedSequence`, `runningCue`, `selectedCue`, `readCueCommand`, `writeCueCommand`). The `AZ:Arm('…')` command stays for macros and for cues that already contain it.
- **Fixtures are armed by default.** The config stores the **disarmed** fixtures (`disarmed: number[]`); every scanned fixture not listed is armed, so newly patched fixtures work as soon as a cue gives them a marker. `Arm('list')` arms exactly the listed fixtures (all others disarmed); `ArmToggle`, `ArmAll`, `DisarmAll` keep their meaning. A saved config without `disarmed` (older builds) means "all armed".
- **Header**: Status · Start/Stop · Setup · Rescan · AZ_SIZE · message. Arm all / Disarm all / Capture / Offset cells are removed (`ArmAll()` / `DisarmAll()` stay as commands).
- **Offset preset pick moves into Setup**: the Setup dialog has a third command, **Pick preset…**, which closes the dialog and starts the pick (§15.2 rules unchanged); the countdown and result appear in the header message cell. `PickOffset()` stays as a command.
- Version 2.0.0.2.
